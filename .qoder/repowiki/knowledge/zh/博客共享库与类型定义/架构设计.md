模块按职责拆分为 `lib/`（运行时函数）和 `types/`（纯 TS 接口），无子包，依赖方向单向：业务 lib → 基础 utils/site → types。
- 站点基址层：`site.ts` 通过 `NEXT_PUBLIC_SITE_URL` / `NEXT_PUBLIC_BASE_PATH` 计算 origin/basePath，被 `seo.ts`、`rss.ts`、`utils.ts` 复用；`utils.ts` 中的 `getAssetPath` 对绝对 URL 透传、相对路径拼接 basePath，供所有含资源的 lib 使用。
- 内容数据层：`posts.ts` 基于 `gray-matter` 读取 `content/posts/<locale>/` 下的 Markdown，产出 `PostMeta`/`Post`，并提供标签/分类聚合与基于 tag 重叠+同分类的相关文章评分；`experience.ts`、`about.ts`、`profile.ts`、`links.ts` 遵循相同模式，各自对应 `types/experience.ts`、`types/link.ts`、`types/profile.ts` 中的 frontmatter 接口。
- 渲染层：`markdown.tsx` 是仅客户端组件（`"use client"`），基于 `react-markdown` + `remark-gfm`，自定义 h1-h4 注入锚点（调用 `toc.slugify`）、代码块折叠/复制、表格/引用样式；`toc.ts` 提供纯函数 `slugify`、`extractToc`、`buildTocTree`，被 markdown 渲染与侧边目录共用。
- SEO 与 Feed：`seo.ts` 集中 `Metadata` 构造器 `buildPageMetadata`、多语言 alternates、Person/WebSite/Breadcrumb JSON-LD；`rss.ts` 用 `unified` 管线将 Markdown 转为 HTML 后拼装 RSS2.0，并自动把相对链接改写为绝对 URL。
- 外部边界：仅依赖 `@/i18n/routing` 获取 locale 枚举，不反向依赖任何页面或 UI 组件。
